文档定位：本 PRD 将当前已交付的「本地可编辑工作台」定义为产品的 MVP，并据此补全产品愿景、功能边界与迭代路线图。 方法论参考 2026 年个人 AI 工作台主流范式（local-first 本地优先、记忆复利、四层架构）与标准 PRD 章节。

1. 产品概述

1.1 产品定位与一句话价值

本地优先、AI 协作驱动的「个人运营中枢」：把散落在对话、自动化任务、记忆、技能与每日亮点中的个人资产，统一收敛为可检索、可编辑、可沉淀的结构化工作台。

1.2 背景与痛点

Miki 处于自由职业起步期，三大方向为自媒体（纯图文 / AI 生成，不露脸不录音）、电商（轻资产）、AI 技术学习。当前个人资产高度碎片化：

  • 信息散落：定时任务在 automations 数据库、记忆在 MEMORY.md、技能在 skills/ 目录、亮点在 highlights.md，彼此割裂。
  • 缺乏沉淀：对话产物用完即弃，难以回溯与复用。
  • 整理耗时：手动在多个文件 / 平台间搬运，打断心流。
  • 飞书实时双向同步结构性不可行：lark-cli 事件订阅不支持多维表格域、飞书记录无单条修改时间 → 无法做「实时回写 / 时间戳新者胜」→ 转向本地优先架构。

1.3 产品愿景

成为 Miki 的「数字联合创始人」：不止记录，更能主动组织、提醒、复用个人知识资产，随时间复利增值。对应 2026 年 AI workspace 范式的核心命题——把注意力从「工具搬运」转向「意图执行」。

1.4 核心价值（USP）

差异化说明
本地优先、隐私可控仅绑定 127.0.0.1，不上云；数据始终在本人机器上。
与运行时同源automations / MEMORY / skills / highlights 即真实数据源，编辑即写回，不存在「影子副本」。
误删可恢复每次写操作前自动生成 .bak 备份。
零依赖轻量Python 标准库 + 原生前端，双击 .bat 即可启动，启动资金几乎为 0。

1.5 目标平台

  • MVP：Windows 桌面（本地 HTTP 服务 + 浏览器），双击 bat 启动、用完关闭。
  • 规划：macOS / Linux 适配；移动端只读视图（v2.0）。

1.6 范围（In / Out of Scope）

In Scope（当前）Out of Scope（当前）
4 类资产的查看、搜索、筛选、编辑、删除、新增；本地写回与 .bak 备份云端多端实时同步、多人协作、AI 自动生成内容、第三方平台（飞书 / 微信 / 电商后台）对接

2. 用户与场景

2.1 用户画像（Persona）

姓名 / 身份
Miki · 自由职业者（单人公司 / solopreneur）
方向
自媒体（幕后纯图文 / AI 生成）、电商（轻资产）、AI 技术学习
技能背景
技术 / 开发类，能读懂脚本，偏好务实干练
约束
启动资金 < 5000；前 6 个月月入目标 5000–1 万；全部时间可投入
偏好
不露脸不录音、轻资产、本地优先、出镜意愿为零

2.2 核心用户故事

  1. 作为自由职业者，我想在一个地方看到今天 / 累计的定时任务、记忆、技能和亮点，以便掌控全局。
  2. 作为内容创作者，我想快速记录一条「决策 / 洞察」亮点，以便日后复盘。
  3. 作为技能使用者，我想修改某个 Skill 的中文说明，以便自己和后续对话快速理解其用途。
  4. 作为记忆管理者，我想删除一条过时的记忆小节，以便保持知识库干净。
  5. 作为单人运营，我希望所有改动都自动备份，以便误删可恢复。

2.3 用户旅程（主路径）

双击 start-workbench.bat → 浏览器自动打开工作台 → 切换 Tab / 搜索 / 按字段筛选 → 点「编辑」改字段或「删除」移除 → 用完点「关闭工作台」。

3.2 模块详述（用户故事 + 逻辑 + 验收）

M1 工作台视图（P0 · 已交付）

  • 功能：4 个 Tab（定时任务 / 记忆 / Skill / 每日亮点），顶部全文搜索，按字段下拉筛选，飞书风格表格，粘性表头（随头部高度自适应），每行统一的「编辑 / 删除」操作列。
  • 验收：① 4 分区数据正常加载并带数量徽标；② 搜索 / 筛选实时生效；③ 每个分区行尾均可见操作列。

M2 定时任务管理（P0 · 已交付）

  • 字段：名称、状态（运行中 / 已暂停）、频率、说明、下次运行。
  • 编辑：名称（文本）、状态（下拉切换）。
  • 删除：软删除——置 deleted_at，视图隐藏但数据库可恢复。
  • 验收：改状态后数据库即时生效；删除后不再出现在视图；所有动作生成 .bak。

M3 记忆管理（P0 · 已交付）

  • 数据源：全局 ~/.workbuddy/MEMORY.md + 项目 .workbuddy/memory/MEMORY.md 的 ## 小节。
  • 编辑：内容（多行文本，写回对应小节）。删除：移除整个 ## 小节。
  • 验收：改写精确落盘对应 MEMORY.md；删除后小节消失；备份文件存在。

M4 技能管理（P0 · 已交付）

  • 数据源：用户级 + 项目级 skills/*/SKILL.md。
  • 编辑：功能说明（写入 skill_cn_override.json 覆盖）。
  • 删除：禁止（删除技能目录风险高，误删难恢复）。UI 不显示删除按钮。
  • 验收：说明改动反映在 override 并重新加载生效；删除入口不存在。

M5 每日亮点（P0 · 已交付）

  • 格式：- [id=HL-...] [类型] 内容；类型：决策 / 学习 / 洞察 / 任务 / 其他。
  • 新增 / 编辑 / 删除：均写回 highlights.md，删除移除对应行。
  • 验收：新增追加到文件末尾；改类型 / 内容写回；删除该行消失。

M6 数据写回与备份（P0 · 已交付）

  • 逻辑：每次写前 shutil.copy2 生成 .bak；采用字段级最小改写（正则替换单行 / 小节），而非整文件重写。
  • 验收：任一写操作后，目标文件同目录存在对应 .bak。

3.3 优先级（MoSCoW）

层级内容
Must（必须有）M1–M7 当前能力（4 分区增改删查 + 备份）
Should（应该有）M8 定时任务新建、亮点按日期排序 / 筛选增强、空状态引导、记忆合并去重
Could（可以有）M9 AI 自动亮点捕获、M10 跨平台 / 移动只读、明暗主题切换、数据导出
Won't（本期不做）云端实时同步、多人协作、第三方平台深度对接

4. 策略设计（AI 部分）

作为 AI 工作台，核心策略需显式说明输入信号、模型逻辑、输出形式与兜底规则（参照 PRD 写作规范）。

策略 A：每日亮点捕获

  • 输入信号：对话中出现的决策、洞察、学习方法、待办、其他有价值片段。
  • 逻辑：AI 主动识别片段类型 → 生成带 id 与类型的结构化行 → 追加到 highlights.md。
  • 输出：highlights.md 新行；工作台「每日亮点」Tab 立即可见。
  • 兜底：识别不确定时仅做人工手动新增，不臆造内容；每日上限保护避免刷屏。

策略 B：记忆沉淀

  • 输入信号：会话结束后的关键结论、用户偏好、项目约定。
  • 逻辑：AI 摘要 → 按主题写入全局 / 项目 MEMORY.md 的 ## 小节（复用 M3 写回通道）。
  • 冷启动：初始为空，随使用自然增长；不预填噪音。
  • 兜底：写入前与现有小节去重合并，避免重复条目。

5. 非功能需求

维度要求
性能本地单用户；页面首屏 < 1s；写入（含备份）< 200ms；数据量百级条目无感知延迟。
安全仅绑定 127.0.0.1，无外部网络暴露；写前备份；密钥走环境变量，不落明文文件；提供 /api/shutdown 关闭端点。
兼容性Windows 10+ / Python 3.11+ / 现代浏览器（Chromium 内核）；规划 macOS / Linux。
可靠性.bak 兜底；端口自动顺延（find_free_port）避免冲突；pythonw 无黑窗启动。
可维护性后端纯标准库、前端单文件无构建；数据源（真源文件）与视图（前端）严格分离，便于替换 UI 而不动写回层。

6. 技术架构

6.1 总体架构（四层，对齐 2026 AI workspace 范式）

层职责当前实现
交互层 Interaction Surface一致的操作用户界面（查看 / 编辑 / 删除 / 审批）workbench_app.html（飞书风格表格）
能力适配层 Capability Adapters采集 + 写回真实数据源的薄适配层workbench_server.py（HTTP 写回层）
记忆 / 知识层 Memory Store版本化、可检索、可审计的个人上下文automations 库 / MEMORY.md / skills / highlights.md
执行内核 Execution Kernel调度 agent、执行策略、持久化状态由 WorkBuddy 运行时提供（对话 + automations 调度）
说明：v1 已覆盖交互层 + 能力适配层 + 记忆层；执行内核由 WorkBuddy 运行时承载，工作台作为「可观察 / 可干预的控制面」与之协同。未来 M9 自动沉淀将让执行内核的产出更主动地回流到记忆层，形成「执行 → 沉淀 → 复用」闭环。

6.2 技术栈

  • 后端：Python 3.11 标准库（http.server / sqlite3 / re / json / shutil）。
  • 前端：原生 HTML / CSS / JS 单文件，无框架、无构建。
  • 启动：.bat + pythonw（无黑窗）+ 自动打开浏览器。

6.3 数据模型

实体主键关键字段真源
定时任务id名称 / 状态 / 频率 / 说明 / 下次运行automations 数据库
记忆主题（全局·/项目·标题）主题 / 内容 / 来源MEMORY.md ## 小节
技能路径名称 / 位置 / 功能说明 / 路径skills/*/SKILL.md + override
每日亮点id（HL-时间戳）类型 / 日期 / 内容highlights.md

6.4 接口契约

方法路径说明
GET/返回飞书风格前端
GET/api/data返回 4 类数据 + 计数 + 可筛选维度
POST/api/update单字段更新
POST/api/update_multi批量多字段更新（一次编辑弹窗改多项）
POST/api/add新增每日亮点
POST/api/delete删除（亮点 / 定时任务软删 / 记忆小节；技能禁用）
POST/api/shutdown关闭本地服务

7. 数据隐私与安全

  • 本地优先：所有个人数据存于本机文件与本地 SQLite，不上传任何云端。
  • 网络边界：服务仅监听 127.0.0.1，外部不可访问。
  • 密钥隔离：第三方凭证走环境变量，不写入工作台管理的任何文件。
  • 可恢复性：写前 .bak + 定时任务软删除，误删可在备份中恢复。
  • 最小权限：Skill 删除禁用，避免误删技能文件导致能力丢失。

9. 风险与开放问题

9.1 风险点

风险等级缓解
前端单文件无构建，复杂功能难扩展中视图与写回层解耦；后续可框架化（不影响后端）
写回真源文件可能破坏结构中.bak + 字段级最小改写；变更前备份
Skill 删除禁用，用户可能困惑低UI 文案说明「为避免误删文件不支持删除」
端口冲突导致起不来低find_free_port 自动顺延；地址写入 workbench_addr.txt

9.2 开放问题（待 Miki 决策）

  • 云端同步：是否要做「本地为主 + 可选加密云端同步」？隐私 vs 多端便利的权衡。
  • 产品化路径：仅个人自用，还是做成人人可装的开源 / 轻量 SaaS？
  • 商业模式：若产品化，采用买断 / 订阅 / 开源捐赠？
  • AI 主动度：自动捕获亮点的「打扰阈值」设多高？（默认保守，仅人工触发）

11. 附录

术语表

  • MVP：最小可行产品（Minimum Viable Product）。
  • USP：独特卖点（Unique Selling Proposition）。
  • HITL：人在回路（Human-in-the-loop），关键决策保留人工干预。
  • Local-first：本地优先，数据先落本机、可离线、隐私可控。
  • 软删除：逻辑删除（置标记），不物理移除，便于恢复。
